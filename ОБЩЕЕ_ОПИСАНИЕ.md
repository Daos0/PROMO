# Описание проекта и структура папок

**Что это.** AI-ассистент (RAG по базе знаний) + набор Python-микросервисов +
интеграции с Bitrix24, Telegram и WhatsApp. Управляется через веб-админку.

**Запуск — в Docker.** Каждый сервис это отдельный контейнер (ai_gateway,
rag_service, bitrix_bridge, боты и т.д.), всё поднимается одним `docker-compose`.
База — PostgreSQL.

**Расширяемость.** Можно подключать любые каналы (WhatsApp, Telegram, новые
мессенджеры) и разные CRM (Bitrix24, amoCRM, …) — добавлением сервиса в
`services/` или адаптера. Включение модулей — через `.env`.

---

## Дерево папок (главное)

```
AI BOT/
├── Dockerfile             # образ для Python-сервисов
├── docker-compose*.yml    # запуск контейнеров (локально / прод)
├── init_db.py             # инициализация базы данных
├── requirements*.txt      # зависимости Python
├── .env                   # ключи, настройки, включение модулей
│
├── INFO/                  # документация по темам (AI/RAG, Bitrix, деплой …)
├── PROMT/                 # промты ассистента (структура, RAG-база знаний)
│
├── frontend/             # ВЕБ-ИНТЕРФЕЙС (Astro):
│   └── src/
│       ├── admin/                 #   ВЕБ-АДМИНКА — часть ядра, есть всегда:
│       │   ├── AdminPage.astro    #     страница панели
│       │   ├── admin-content.js   #     вход и навигация
│       │   ├── ai-console.js      #     раздел «AI»
│       │   ├── bitrix-console.js  #     раздел «Битрикс»
│       │   ├── leads-console.js   #     раздел «Заявки»
│       │   └── styles/            #     стили админки
│       ├── ai-widget/             #   чат-виджет ассистента (ДОПКА)
│       └── pages, layouts, …      #   САЙТ (ДОПКА) — структура своя под задачу
│
├── services/             # PYTHON-МИКРОСЕРВИСЫ (каждый = контейнер):
│   ├── ai_gateway/                #   мозг ассистента: провайдеры, промт, память, RAG
│   ├── rag_service/               #   база знаний: чанкинг, эмбеддинги, поиск, rerank
│   ├── bitrix_bridge/             #   мост в Bitrix24:
│   │   ├── channels/              #     каналы: bitrix, telegram, whatsapp
│   │   ├── routes/                #     oauth (подключение), admin
│   │   └── runtime/               #     приём вебхуков, фоновые задачи
│   ├── leads_service/             #   заявки: разбор, хранение, отправка в CRM
│   ├── wa_service/                #   WhatsApp (канал — допка, по необходимости)
│   └── …                          #   любой другой канал / сервис / CRM добавляется сюда
│
├── shared/               # ОБЩИЙ КОД для сервисов:
│   ├── db/                        #   модели БД и репозитории (models_*, repos/)
│   ├── ai/                        #   общий AI-модуль
│   ├── broadcast/                 #   очередь рассылок
│   ├── leads/                     #   разбор заявок, адаптер CRM
│   ├── prompts/                   #   хранилище промтов
│   ├── render/                    #   форматирование ответа (web / telegram / whatsapp)
│   ├── schedule/                  #   рабочие часы и правила
│   ├── config.py                  #   общие настройки
│   └── rag_profiles.py            #   профили баз знаний
│
├── src/                  # ТЕЛЕГРАМ-БОТЫ (допка):
│   ├── app_core/                  #   ядро бота: запуск, конфиг, воркер рассылок
│   └── bots/
│       ├── client_bot/            #     бот для клиентов (консультации, CRM)
│       ├── owner_bot/             #     бот владельца (админка из Telegram)
│       └── common/                #     общие команды
│
├── api/                  # FastAPI: основной API
├── chat_api/             # API чата (авторизация, рабочие часы, роутинг)
├── dao/                  # API админки (AI, Bitrix, заявки, пользователи)
└── deploy/               # ДЕПЛОЙ: Caddyfile, Dockerfile'ы сервисов, env, vpn
```
